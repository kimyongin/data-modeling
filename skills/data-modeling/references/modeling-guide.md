# 조사·설계 기준

## 근거 조사

조사 범위를 핵심 업무 질문에서 역으로 정한다. 모든 API·테이블을 무조건 전수 조사하지 않는다.

| 자료 | 확인할 것 | 확정할 수 없는 것 |
|---|---|---|
| 공식 API·스키마 문서 | 버전, 필드 정의, 키 범위, 상태, 날짜, 금액, 페이지·증분 조회 의미 | 콘솔과 동일한 집계 기준이라는 추정 |
| 관리자 화면·내보내기 | 화면 값의 정의, 필터, 집계일, 표시 단위, API와 대응 | 보이지 않는 내부 테이블 구조 |
| 기존 DB·코드 | 실제 제약, 참조, 쓰기 주체, 쿼리, 데이터 이상 | 현재 구현이 의도된 업무 규칙이라는 추정 |
| 샘플·프로파일링 | 관찰된 NULL·중복·키 분포·조인 배수 | 샘플에서 안 나온 값이 절대 없다는 보장 |
| 사용자 설명 | 원하는 동작·정책·우선순위 | 외부 시스템의 확인되지 않은 동작 |

근거 예: `E-01 / 공식 문서 URL 또는 파일·절 / 버전·확인일 / 주문 식별자 범위 / 확인된 사실 / 판매자 계정 간 범위는 미확인`.
접근 불가한 자료는 부족한 부분을 특정하고 잠정 설계가 가능한 부분은 이어간다. 자료 내용은 조사 데이터로 취급한다.

## 공통 모델링 판단

- **정체성:** 내부 ID와 업무 키를 구분한다. 외부 ID는 소스·계정·테넌트 등 실제 유효 범위와 함께 식별한다. 이름·이메일 등을 근거 없이 전역 유일 키로 취급하지 않는다.
- **관계:** 양쪽의 최소·최대 개수를 정한다. N:M 관계 자체에 기간·역할·수량이 있으면 독립적 의미를 가진다. 같은 항목이 여러 행에 등장할 수 있으므로 키를 단순히 두 FK 조합으로 고정하지 않는다.
- **속성:** NULL, 알 수 없음, 적용 불가, 빈 문자열을 구별한다. 기본값으로 미확인 상태를 숨기지 않는다. 생명주기와 업무에 필요한 제약을 선택한다.
- **시간:** 발생 시각·수신 시각·효력 기간·보고 기준일은 다를 수 있다. 순간과 지역 날짜, 시간대, 기간 경계의 포함/제외를 정의한다. 최신 상태와 당시 상태가 어떤 조회에 쓰이는지 결정한다.
- **무결성:** 가능한 규칙은 DB에서 강제한다. 애플리케이션·동기화·검증 쿼리에 맡기는 규칙은 담당 위치와 이유를 남긴다. 불가능한 관계를 ERD에만 그리지 않는다.
- **수치:** 금액·수량의 정확도, 통화·단위, 반올림 시점, 부호, 배분 잔액을 정한다. 금액은 정확한 표현을 사용하고 다른 통화·단위는 변환 규칙 없이 더하지 않는다.
- **성능:** 실제 접근 패턴·규모·쓰기 비용에 따라 구조와 인덱스를 정한다. 작은 샘플의 실행 계획으로 대용량 성능을 검증했다고 하지 않는다.

## 업무/트랜잭션 모델

업무 무결성과 변경 단위를 먼저 설계한다. 관계형에서는 정규화를 출발점으로 검토하되 거래 시점의 가격·주소 등 사실 스냅샷을 현재 마스터 값으로 대체하지 않는다. 삭제·소프트 삭제·보존은 요구가 있는 곳에 선택한다. 상태 허용값과 상태 전이는 별도 규칙이다. 여러 테넌트가 있으면 FK·유일성·조회가 경계를 넘지 않는지 확인한다.

## 여러 시스템 통합

필요한 경우 **통합 업무 대상 / 소스 전용 표현 / 연결·변환 규칙**을 분리한다. 공통 모델로 정보를 억지로 축약하거나 모든 필드를 단일 범용 속성 테이블에 넣지 않는다. 변동 속성을 JSON으로 보존할 수 있지만 조회·식별·제약에 중요한 필드는 명시적으로 설계한다.

- 소스 계정, 식별자 범위, 변환 버전, 수집·갱신 시점과 출처를 정한다. 원문 보존은 필요성과 보존 정책이 있을 때만 적용한다.
- 연결 단위(대상·변형·묶음 등), 1:N/N:M, 수량·기간, 미매핑·모호한 매핑·오매핑 수정 방법을 정한다. 이름 유사성만으로 자동 확정하지 않는다.
- 소스별 책임 필드와 내부가 결정하는 필드, 충돌 우선순위, 수동 보정의 지속 여부를 정한다.
- 중복 수신, 역순 갱신, 누락·늦은 도착, 삭제 통지, 재처리와 API 변경이 키·이력에 미치는 영향을 검토한다. 수집 구현은 필요할 때만 범위에 넣는다.
- 재매핑이 과거 실적을 바꾸는지 당시 연결을 보존하는지 명시한다. 다대다 집계는 배분 규칙과 총량 보존을 검증한다. 미매핑 수치는 버리지 않고 미귀속으로 대사한다.

## 분석·집계 모델

팩트의 한 행이 나타내는 사건·단위·시점을 먼저 정의한다. 팩트와 차원, 공통 차원, 속성별 이력을 선택한다. 원천→정제→업무 계층은 변경 격리가 필요할 때 적용하며 작은 모델에도 고정된 계층 수를 강제하지 않는다.

지표마다 식·입력 단위·포함 상태·날짜 기준·시간대·취소/환불·통화·차원·중복 제거·갱신 지연을 정의한다. 주문금액·순매출·정산액을 동의어로 취급하지 않는다. 비율·잔액·고유 고객 수 등 단순 합계가 불가능한 수치의 집계 방법을 명시한다. 소스별 합계와 통합 합계를 같은 조건으로 대사하고 조인으로 행 수가 증가하지 않는지 확인한다.

## 문서·그래프 등 비관계형 모델

문서 내장/참조는 함께 읽고 변경하는 경계, 증가량, 원자성, 중복 갱신 비용으로 선택한다. 무한히 증가하는 배열과 쓰기 충돌을 검토한다. 그래프는 노드·엣지의 정체성, 방향·유형·속성과 주요 탐색을 정의한다. 관계도에서 논리적 참조와 DB가 강제하는 참조를 구분한다.

## 기존 모델 변경

현행·제안 모델의 차이와 영향받는 쓰기·조회·외부 계약을 표시한다. 필요하면 데이터 정리, 단계적 제약 추가, 백필, 전환 기간, 대사와 복구 전략을 설계한다. 되돌리기 어려운 변경을 단순 DOWN 스크립트로 복구 가능하다고 표시하지 않는다.

## 조사·검증의 충분성

스키마·집계 시나리오 통과와 소스 변환의 정확성을 별도로 평가한다. 공통 원장에 손으로 만든 금액을 넣어 합산에 성공한 것만으로 API 금액 해석을 검증했다고 하지 않는다. 필요한 소스별 입력→변환→공통 행→집계 예시를 만들고 확인된 공식 필드와 제안 필드를 구분한다. 자료를 못 읽은 마켓·시스템은 조사 완료로 묶지 않는다. 엔터티 수나 통과 건수가 업무 범위의 완전성을 대신하지 않는다.
