# 데이터 모델링

업무 질문에 답하고 예외·정정·변경에도 의미를 유지하는 모델을 설계한다. 산출물은 **모델 JSON 2.0**이며, 스킬에 동봉된 공통 뷰어로 검토한다. 새 사례마다 HTML이나 화면 코드를 만들지 않는다.

## 작업 선택

- **새 모델:** 요구·범위·업무 용어와 한 건의 의미를 정하고 조사 → 규칙·누락 → 대안 → 모델·샘플로 진행한다.
- **기존 모델 수정:** 현재 JSON과 근거를 먼저 읽고 영향을 받는 규칙·모델·샘플·결과를 함께 갱신한다. 이전 설계 문서와 실제 운영 DB를 구별한다.
- **스킬·도구 유지보수:** [UI 지침](references/viewer-ui.md)과 개발 저장소의 `dev/README.md`를 읽고 공통 코드·동봉 뷰어·예제·설치 패키지를 함께 확인한다. 조작·상태 복원뿐 아니라 빠른 연속 전환·실패 후 복구와 화면 범위/데이터셋의 독립성을 회귀 검사한다. Node 검사와 실제 시각 검사를 구별한다. 일반 모델링에는 개발 도구가 필요 없다.

## 설계 판단

1. 사용자·행동·조회 질문·성공 기준을 안정적인 요구사항 ID로 정리한다. DB가 미정이면 물리 구현을 확정하지 않는다.
2. [조사·설계 기준](references/modeling-guide.md)에 따라 원문 근거와 한계를 확인한다. 사실·가정·제안·미확인을 구별하고 접근하지 못한 API·관리자 자료를 조사했다고 쓰지 않는다.
3. [설계 검토](references/design-review.md)에 따라 복잡도에 맞춰 대안·빠진 업무 규칙·변경 영향을 검토한다. 규칙의 **설계 반영 상태와 업무 합의 상태**는 별도로 기록한다. 단계마다 승인을 반복하지 않는다.
4. 모델에 식별·한 행의 의미·속성·관계 양쪽 개수·상태·시간·삭제·정정을 명시한다. PK·유일 조합·물리 FK는 명시적인 필드로 작성하고 표시용 문자열에서 추측하지 않는다. 논리 연결과 DB에서 강제하는 FK를 구별한다.
5. 정상·경계 상황 중 설계 선택을 구별하는 샘플을 작성한다. ID만으로 뜻을 알기 어려운 모델에는 `display_attributes`로 계정·판매 항목·상품 옵션 등의 업무 식별 속성을 명시한다. [쉬운 설명](references/report-writing.md)을 따르고 원문은 요구사항·규칙·결정 각각 한 곳에만 쓴다. 합성·비식별 자료를 사용하고 인증정보를 넣지 않는다.

## JSON 작성과 확인

[데이터 계약](references/review-contract.md), [직접 작성 안내](references/model-json.md), [완전한 예제](references/example-model.json)를 사용한다.

- `references/schemas/model-2.0.0.schema.json`에 맞는 `<사례>.model.json`을 작성한다. 문서 정보, 요구사항, 규칙, 결정, 쟁점, 모델, 데이터셋·시나리오, 근거를 구분한다.
- `scripts/validate_model.py <사례>.model.json`으로 형식·ID·참조·모든 샘플·결과 대응을 검사한다. 경고를 읽고 누락을 보완하거나 남은 한계로 기록한다. 통과가 업무 규칙의 완전성을 뜻하지 않는다.
- 파일 정리가 필요하면 `scripts/build_model.py source.json --output <사례>.model.json`을 쓴다. 원본을 보존하고 JSON과 생성 기록만 만든다. [생성 절차](references/rendering-workflow.md)를 따른다.
- 실제 확인하지 않았으면 `observations: []`를 유지한다. 확인한 시나리오에만 방법·범위·시점·결과와 현재 대상의 내용 지문을 기록한다. [결과 대응](references/result-integrity.md)을 따른다. 생성기는 성공 기록이나 새 지문을 임의로 만들어 주지 않는다.
- 동봉된 `assets/model-viewer.html`에서 JSON을 가져와 스펙·ERD·속성·설명·샘플을 확인한다. 실제 브라우저 확인을 못 했다면 코드/번들 검사와 구별해서 보고한다.

결과 JSON 링크와 뷰어 위치, 주요 판단·실제로 확인한 범위·남은 결정을 전달한다. SQL·검증 전용 탭은 추가하지 않는다. 조사·검토 권한을 운영 변경·외부 배포 권한으로 확대하지 않는다. 현재 계약만 지원하며 이전 형식용 필드·호환 모드를 새 데이터에 넣지 않는다.
