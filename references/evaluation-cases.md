# 행동 평가용 요청

실제 사용에서 선택해 사용한다. 사례를 외워 답하도록 특정 도메인 구조를 강제하지 않는다. 아래는 테스트 요청이며 조사·모델링을 이미 완료했다는 뜻이 아니다.

## 조사·통합 평가: 여러 오픈마켓

> 쿠팡·네이버·11번가·G마켓의 공식 오픈API와 접근 가능한 관리자 콘솔 자료를 조사해 각 마켓의 데이터 모델을 파악해줘. 우리 시스템의 하나의 상품·옵션을 기준으로 마켓 전용 모델들을 연결하고, 상품 A를 선택하면 마켓별 매출과 통합 매출을 볼 수 있게 설계해줘. 요구사항·근거·매핑·집계 규칙과 ERD, 샘플 시나리오를 담은 모델 JSON만 만들고 기존 공통 뷰어에서 검토하고 싶어. 접근하지 못한 자료와 미확인 내용은 구별해줘.

관찰점: 공식 필드와 가상 필드 구별, 계정별 ID 범위, 상품/옵션/등록 단위 구별, 매출 정의, 취소·반품·중복 수집·미매핑·재매핑, 소스별·통합 합계 대사. 문서에 없는 구조나 의미를 사실로 단정하지 않고 콘솔 접근권한을 가정하지 않는다.

## 범용성: 조직별 프로젝트 관리

> 사용자가 여러 조직에 속하고 조직마다 역할이 달라. 프로젝트와 담당 업무를 관리하며 담당자의 조직 탈퇴 후에도 과거 업무 기록은 남겨야 해. DB는 아직 정하지 않았어. 모델 JSON과 샘플을 만들어줘. HTML은 만들지 말고 기존 공통 뷰어에서 확인해줘.

관찰점: 멤버십과 사용자 구별, 조직 경계, 현재 권한과 과거 기록, DB 미정 상태의 논리 설계. 불필요한 통합/소스 모델과 DW 계층을 추가하지 않는다.

## 범용성: 장비 시계열 분석

> 센서 측정값으로 일별 평균과 장애율을 보고 싶어. 데이터가 늦게 도착하거나 같은 관측이 재전송되기도 해. 센서의 소속 현장이 바뀔 수 있어. 검토용 모델을 설계해줘.

관찰점: 관측 단위, 사건/수신 시각, 시간대, 중복 제거, 단위, 가중 평균·분모, 당시 현장 기준.

## 범용성: 기존 문서형 설계 수정

> 기존 문서형 콘텐츠 DB에서 게시물마다 계속 늘어나는 수정 이력을 배열로 저장하고 있어. 게시물 조회는 빠르게 유지하면서 특정 시점 내용을 복원하고 싶어. 전체 재설계 없이 변경안을 보여줘.

관찰점: 기존 범위, 문서 증가·동시 변경·이력 탐색, 관계형 DDL 강제 여부, 전환·복구·검증 범위.

## 공통 평가

요구사항→모델→실행 예시 추적, 가정/근거 구별, 목적에 맞는 패턴, JSON만 생성하고 기존 뷰어에서 확인, 실행한 경우의 기대값·실제값 비교, 잘못된 데이터 거부, 미검증 범위, 승인 전 초안 상태를 확인한다.

## 기존 공통 뷰어의 행동 평가

1440×900·1920×1080·1366×768에서 개요의 큰 그림과 한 화면 노출, 스펙의 공통 항목 우선 순서·원문 보존, 참조 탭 이름, 내부 이동 버튼·참조 모달 없음과 안전한 외부 원문 링크를 확인한다. ERD 제목을 좁은 패널에서도 말줄임 없이 읽고 설명의 섹션별 역할·선택과 영향·관계 이유·남은 판단·실제 확인 결과가 구분되는지 직접 읽는다. 기존의 정확한 업무/확인 사항 범위·모든 PK/FK·일반 속성·전 행 샘플·실패/미실행·오프라인·키보드·미니맵·양쪽 경계·카메라·탭별 선택/스크롤·긴 값·문서 스크롤 없음도 회귀 검토한다.

설계 이유·출처·검증의 모든 항목을 목록 스크롤로 선택하고 본문 끝까지 접근한다. 검색 결과/빈 결과, 탭별 검색·선택·목록/본문 스크롤 보존, 일반 텍스트로 된 내부 참조의 코드:타이틀 표기와 중복 이동 버튼·모달 없음, 상위/하위 탭 키보드와 포커스, 안전한 원문 링크를 확인한다.

모델은 공통·소스 전용 엔터티 전체를 포함해야 한다. 영역별 primary/context 집합은 직접 참조 부모만 보완하고 재귀 확장하지 않는다. 엔터티 상자에는 PK/FK와 복합 FK의 모든 구성 열만 표시하고 일반/UQ 전용 열은 제외한다. 오른쪽 속성에는 전체 속성과 설명이 있어야 한다. 관계선 클릭/키보드는 카메라를 바꾸지 않고 오른쪽 설명에서 해당 관계를 만든 이유를 표시한다. REL-N은 그래프에서 제외한다. 설명에는 엔터티별 필요성·대가·위험과 직접 관련 근거가 있어야 하며 미작성을 숨기지 않는다.

중앙 샘플 데이터 드로어의 모든 행·긴 값·마지막 열을 내부 수직/수평 스크롤로 확인하고 머리글·행 수는 고정한다. 같은 엔터티의 탭 전환·창 크기 변경 후 스크롤을 보존한다. 모델 선택·탭 전환·관련 정보 탐색 뒤 영역·배율·위치·SVG 유지, 수동 줌/드래그·전체 복귀도 확인한다. 긴 제목·빈 데이터·시나리오 없음·실패/미실행을 점검하고 다른 도메인 예시에서도 동일하게 동작해야 한다.

SVG 텍스트 위에서 실제 마우스 드래그를 시작하여 화면은 이동하지만 브라우저 텍스트 선택과 우발적 엔터티/관계 선택이 생기지 않는지 확인한다. 속성 설명·샘플은 계속 선택·복사 가능해야 한다. 미니맵은 ERD 안 오른쪽 아래에 있고 현재 영역의 전체 노드 수와 배치, 현재 보기 프레임이 일치해야 한다. 지도의 여러 지점을 실제 클릭해 정확한 좌표로 이동하고 배율·선택·SVG는 유지되는지 확인한다. 여백/종횡비·전체 맞춤·확대/축소·팬·크기/업무 영역 변경·방향키·탭 왕복과 중복 ID/이벤트 없는 동작을 검증한다.

모든 내부 참조 텍스트가 코드:타이틀과 일치하고 버튼·링크·모달이 아닌지 확인한다. 외부 원문 링크만 참조 탭에 남기며, 필요한 설명·설계 대안·미결 선택지·실제 확인 결과는 본문에서 읽을 수 있어야 한다. 출처의 조사 한계와 확인 결과의 실패/미실행을 숨기지 않는다.

미니맵은 초기 접힘 상태에서 작은 열기 버튼만 보이고, 열기/닫기 및 키보드 전환에 배율·위치·선택·SVG가 바뀌지 않아야 한다. 열림 상태는 업무 영역·탭 왕복에도 보존한다. 상단에 중복 속성 정의 버튼은 없어야 한다. 병렬 가지가 많은 영역을 검토해 rankdir=LR만 적용된 세로 쌓임과 가로 분산 후보를 비교한다. 선택 결과의 실제 엔터티/관계 집합·개수, 겹침 없음, 읽기 배율을 확인하고 보조 순서 제약이 실제 관계로 노출되지 않도록 검증한다.

밀집 배치 개선은 같은 뷰포트의 이전 결과와 비교해 화면 맞춤 배율·실제 관계 경로 총길이·엔터티 점유율을 측정한다. 단순히 간격만 좁히거나 전체를 한 줄로 펴지 않고 직접 연결된 모델과 인터페이스 허브 주변 가지가 가까운 묶음으로 보이는지 시각 확인한다. 전체/상품/주문 등 각 영역에서 모델·관계 집합과 개수가 동일하고 노드 겹침·보조 관계 노출이 없어야 한다. 미니맵의 새 배치/범위 동기화, 선택·관계 상세·탭 왕복 시 카메라/SVG 보존, 다른 도메인 예시와 측정용 숨김 SVG 제거도 확인한다.

상위 4개 탭의 목적·내용은 상단 헤더 제목 바로 아래 `메뉴 이름 - 설명` 형식의 작은 설명으로, 모델 상세의 속성·설명 탭과 중앙 샘플 드로어는 해당 패널 안의 안내로 표시되는지 확인한다. 참조의 단일 목록 항목 선택은 상위 탭 설명을 바꾸지 않아야 한다. 탭을 바꾸면 설명도 바뀌고 목록 선택은 현재 안내를 유지하고 상위 탭 전환은 대상 탭 설명을 표시해야 한다. 세 가지 데스크톱 해상도에서 안내가 잘리지 않고, 본문 스크롤과 분리되며, 문서 스크롤·ERD 카메라 초기화가 생기지 않아야 한다.

## 범용 회귀 입력의 선택 기준

프로젝트 관리 외에 회의실 예약(시간 구간 경계·취소·다대다 조인), 학습 진도(복합 FK·이벤트 정정·중복·늦은 도착)처럼 다른 업무 단위와 오류를 가진 합성 사례를 사용한다. 같은 생성기에 입력하고 목표→실제 절차→모델/샘플→설계 이유→근거→검증의 동일한 형식을 확인한다. 도메인별 표·필터·모델을 생성기 코드에 추가해 사례를 통과시키지 않는다.

논리 문서 연결은 FK가 아닌 관계, 순환·자기 참조, domains 없음, 빈 샘플, 해석 미작성, 실행 보고서 없음으로 점검한다. 대량 업무 영역·긴 제목·긴 샘플·긴 참조 본문은 각 탭의 내부 스크롤과 내용 잘림을 점검한다. 의도한 실패·미실행·통과가 공존하는 보고서는 상태를 숨기지 않는지 확인하되 정상 SQL 통과 개수에 합산하지 않는다. 합성 입력의 성공을 실제 서비스 명세 조사나 운영 DB 검증의 증거로 사용하지 않는다.

고정 의존성을 설치한 Python 회귀 실행기와 선택적 브라우저 실행기는 `review-contract.md`의 재실행 절을 따른다. 실행 결과 파일·검증 범위·직접 확인한 스크린샷을 남기고 아직 시도하지 않은 NoSQL 실행·대규모 모델·대상 DB 동시성은 미검증으로 남긴다.

## 비개발자 관점의 설명 검토

회의실 사례에서 “10시~11시 뒤에 11시 예약은 왜 허용되는가”, “설비가 2개여도 참석자는 왜 2명인가”를 SQL 없이 설명할 수 있는지 읽어 본다. 학습 사례에서는 “변경 기록 4건인데 완료 수업은 왜 1개인가”, 오픈마켓 사례에서는 “55,000원은 어떤 금액이며 마켓별 금액과 어떻게 맞는가”를 확인한다. 업무용 항목 이름과 원래 필드명, 구체적인 예와 검토 질문이 함께 보이는지 확인한다.

자동 검사는 작성된 예와 설명의 누락, 확인 상태와 기대 동작, HTML에 실행 코드·원시 결과가 없는지, 잘못된 설명 입력의 거부와 화면 오버플로를 확인한다. 문장 길이나 특정 단어 개수로 친절함을 판정하지 않는다. 직접 읽은 설명이 샘플·SQL·실제 결과와 일치하는지도 따로 대조한다.

## 판단과 근거의 일치

취소 상태만 있는 모델이 변경자·사유·변경 이력까지 추적한다고 주장하지 않는지 대조한다. 스펙 본문의 쟁점이 엔터티별 위험을 빠뜨리지 않는지, 정책 선택·설계 제외·실행 미검증이 구별되는지 확인한다. 요구사항에서 모델·결정·예시 결과와 남은 한계로 이어지는 연결을 확인한다.

1366×768에서 예약을 고른 직후 첫 속성 내용을 읽을 수 있어야 하며 긴 예·질문은 설명에서 확인한다. 업무용 예약 데이터의 첫 행이 표 전체를 압도하지 않고 원래 ID 옆에 정확한 참조 이름이 보이는지 확인한다. 경계 테스트는 별도로 긴 값의 끝·전체 행·가로/세로 스크롤을 확인한다. HTML 밖의 내부 검증은 행 순서 변경·복합 식별·같은 키의 여러 행·누락/추가 행·중복 수·미실행·원인이 다른 오류를 포함한다. 자동 검사가 통과해도 실제 업무 설명과 맞는지는 따로 읽고 판단한다.

개요는 3개 데스크톱 해상도에서 내부 스크롤 없이 읽고 전체 원문은 요구사항의 범위 항목에서 확인한다. 요구사항·쟁점의 설명과 선택지는 본문에 있고 내부 참조 텍스트가 이동을 만들지 않아야 한다. 참조의 근거/제작/용어 왕복과 상위 탭 왕복에서 검색·선택·각 본문 스크롤이 독립적으로 유지되는지 확인한다.

## 요구사항 중심 통합 검토

4개 상위 탭만 표시하고 스펙에서 요구사항을 선택하면 요약·설계안·남은 결정만 보이고, 실제 확인 결과는 모델 탭에서 업무 영역에 맞게 보이는지 확인한다. 여러 요구사항에 공유되거나 연결이 없는 쟁점·설계안도 공통 항목에서 누락 없이 보인다. 관련 ID는 일반 텍스트로 보존하며 핵심 설명과 선택지는 현재 본문에서 읽을 수 있어야 한다. 스펙 검색에는 관련 쟁점·설계안도 포함한다. 확인 예시는 모델 탭의 확인 사항 목록에서 선택하며 스펙 본문에 중복 이동 버튼을 만들지 않는다.

체크리스트는 업무 영역별 상황·기대 동작·관찰 결과를 텍스트로 제공한다. SQL/결과 표/JSON/펼치기/수동 체크 기능은 없으며 HTML 내장 데이터에도 실행 SQL·원시 결과가 없다. 실패·미실행·준비 오류와 실제 통과를 올바르게 구분하고 내부 확인 작업 자체는 계속 수행한다.

## 스펙 문맥 확인

회의실의 예약 시간 스펙에서 왜 현재 상태와 시간을 저장하는지, 취소한 시간은 왜 다시 쓸 수 있는지, 준비 시간·취소 이력 중 무엇이 미정인지 한 흐름으로 설명할 수 있어야 한다. 학습 진도와 마켓별 매출에서도 요약→설계안과 샘플 예→남은 결정 순서가 같은지 읽는다. 근거 없는 설계 설명을 자동 합성하지 않고 legacy 입력의 이유·미작성도 유지한다. 제목 변경뿐 아니라 단계 안내·반복 경고·중복 성공 문장·경쟁하는 두 열 카드가 제거됐는지 확인한다.

## 모델과 연결한 업무 확인

스펙에는 요약·설계안·남은 결정만 있고 실행 목록은 없어야 한다. 확인 사항 탭의 전체 항목이 원본 시나리오 집합과 중복 없이 일치하는지 대조한다. 도메인은 ERD의 표시 범위를 바꾸며 확인 목록을 복제하지 않는다. 확인 사항 범위가 정해진 뒤 모델을 고를 때 SVG/카메라는 유지되고, 명시한 모델만 강조되며 전체 복합 PK가 일치한 기본 행만 강조되어야 한다. 밖에 있는 모델·미작성 연결·기본 표에 없는 추가 입력은 추측하지 않는다. 실제 실패·미실행·준비 오류에서 observation을 성공처럼 표시하지 않는다.

## 통합 탐색·관계 의미·불렛 회귀

스펙의 독립 규칙은 작성한 불렛 그대로 읽히며 원문 문단과 중복되지 않는다. 관계선은 설명의 rationale로 연결되고 표·카디널리티 반복이나 관계 전용 탭이 없어야 한다. 오른쪽은 속성/설명 두 탭이다. 왼쪽 업무 영역/확인 사항 탭에서 전체 시나리오가 원본 ID별 한 번씩 표시되고, 여러 영역을 바꾸어도 중복 목록이 생기지 않는지 확인한다. 확인 사항 선택 시 명시한 모델과 직접 참조 대상만 보이고 전체 보기로 전체 모델이 복원되어야 한다. 빈 목록·영역 없음·28개 영역·긴 확인 제목에서도 마지막 항목 접근, 탭별 스크롤·선택·키보드 포커스를 확인한다.

## 중앙 공간과 오른쪽 상세 회귀

중앙은 도구 모음/캔버스와 기본 닫힘 샘플 드로어로 구성하며, 캔버스는 항상 남은 높이 전체를 차지한다. 드로어는 하단에서 겹쳐 열리고 닫혀야 한다. 오른쪽 두 탭의 안내·키보드 이동·샘플 표 전체 행/열·스크롤 보존을 확인한다. 왼쪽 확인 사항은 해당 ERD 범위와 설명의 결과 한 곳으로 연결되고, ERD에서 관련 모델을 선택한 뒤 샘플 데이터 드로어에서 정확한 기본 행이 강조되는지 확인한다. 같은 확인 사항 범위의 탭 전환과 모델 선택 전후의 ERD SVG/배율/위치가 같고 실제 결과의 실패·미실행 상태도 유지되어야 한다.

## 탐색 탭과 너비 조절 회귀

영역/확인 사항 탭 전환의 목적·선택·키보드·개별 목록 스크롤과 원본 ID별 1회 표시를 확인한다. 경계를 실제로 드래그해 두 패널 너비가 반대로 바뀌는지, 최소/최대/기본 너비와 키보드 복귀가 동작하는지 확인한다. 드래그·탭 왕복·창 크기 변경 중 ERD SVG/배율/위치·선택은 같고 미니맵 프레임만 새 캔버스 크기에 맞아야 한다. 포인터 취소 이후 텍스트 선택과 일반 클릭이 정상 동작해야 하며 문서 스크롤이 없어야 한다.

## 확인 사항 범위와 왼쪽 경계 회귀

각 확인 사항의 primary=entities, context=primary가 직접 참조하는 외부 대상 한 단계, visible=primary∪context를 실제 노드/관계 집합과 대조한다. 다른 확인 사항·업무 영역으로 바꾸어도 이전 SVG/캐시가 섞이지 않아야 하며 전체 보기로 모든 모델·관계가 복원되어야 한다. 같은 확인 사항 재선택과 해당 모델/샘플/탭 전환은 SVG·카메라를 유지한다. 연결 없는 예시는 추측하지 않는다. 왼쪽 경계를 실제로 끌어 왼쪽 너비와 중앙 너비가 반대로 바뀌고 오른쪽 너비는 유지되는지 확인한다. 양쪽 최대 너비에서도 중앙 최소 공간과 문서 스크롤 없음, 각각의 기본 복귀·키보드·포인터 취소·사용자 너비 보존을 검토한다.

## 큰 그림과 상단 정리 회귀

개요의 실제 SVG 노드·연결·선 의미가 입력 diagram과 정확히 일치하고 읽을 수 있는지 확인한다. 카드 목록에 임의의 화살표를 덧붙이지 않는다. 여러 사례·순환 연결·자기 참조·기존 structure/overview 없는 입력·대체 텍스트를 점검한다. 문서의 직접 자식은 한 줄 app header/작업 공간/footer이며 제목·주 메뉴가 같은 상단 바 안에 있어야 한다. 각 상위 탭 설명은 헤더의 제목 바로 아래에 `메뉴 이름 - 설명` 형식으로 작게 있고 본문/탐색 영역에 중복되지 않으며 참조 왼쪽에 개별 근거 자료·제작 과정·용어 안내가 하나의 목록으로 나오고 오른쪽에 본문이 나와야 한다. 별도 분류 메뉴·중간 목록·하위 탭이 없어야 한다. 항목 전체 검색과 빈 결과, 자료가 없는 입력, 방향키 위/아래·Home/End, 항목별 본문 스크롤과 목록 위치·선택 보존을 확인한다. 세 가지 해상도에서 개요 한 화면·본문 공간·문서 스크롤 없음·상위/하위 탭 키보드와 선택/스크롤·ERD 카메라·중복 DOM ID 없음·오프라인을 검토한다.

## 중앙 샘플 드로어

모델의 오른쪽 상세는 속성·설명 두 탭이다. 샘플은 중앙 도구 모음의 “샘플 데이터 보기/닫기”로 여는 하나의 드로어에만 표시한다. 기본은 닫힘이며 중앙 하단에서 위로 열려 캔버스 일부에 겹친다. 드로어는 중앙 패널 너비를 사용하고 문서 스크롤·모달·별도 오른쪽 샘플 탭을 만들지 않는다. 열기/닫기는 ERD SVG·배율·위치·선택과 좌우 패널 너비를 바꾸지 않는다. 오른쪽 설명의 실제 확인 결과는 그대로 읽을 수 있어야 한다.

드로어는 선택 모델의 제목·전체 행 수·모든 값·원래 ID와 정확한 참조 이름을 제공하며 내부 가로/세로 스크롤·고정 표 머리글·정확한 확인 행 강조를 유지한다. 모델별 표 스크롤과 드로어 열림 상태를 모델/업무 영역/확인 사항/상위 탭 전환에 보존한다. 숨겨진 표의 0 크기 때문에 복원 위치가 사라지지 않게 한다. 드로어의 닫기와 내부 Escape는 드로어만 닫고 열기 버튼으로 포커스를 돌린다. aria-expanded/aria-controls와 키보드 조작을 제공하며 표의 휠·드래그·텍스트 복사가 ERD 팬/줌으로 전달되지 않게 한다. 최소 중앙 너비·긴 제목·많은 속성·긴 값·빈 행·창 크기 변경에서도 조작과 모든 값에 접근할 수 있는지 확인한다. 미니맵의 독립적인 열림 상태와 좌표 이동은 유지한다.

샘플 드로어 위쪽 경계는 위/아래 드래그로 높이를 조절한다. 가로 separator와 aria 값, 위/아래 방향키·Home/End·Enter/두 번 클릭 기본 복귀를 제공한다. 사용자가 정한 높이는 닫기/열기·모델/업무 영역/확인 사항·상위 탭 전환에 유지하고 창 크기 변경 시 캔버스 안으로 제한하되 선호 높이는 기억한다. 도구 모음과 ERD 일부는 남겨 두며 높이 조절은 ERD SVG·카메라·선택·좌우 너비를 바꾸지 않는다. 드래그 중 텍스트가 선택되지 않고 포인터 취소·캡처 해제·닫기 후 조절 상태가 해제되어야 한다. 오른쪽 모델 상세 탭 이름은 **속성 | 설명**이다.

## 데이터만 작성하는 고정 렌더러 평가

새 사례에서는 standard 모델 JSON만 작성·검사하여 기존 공통 뷰어에서 연다. 기본 생성기가 JSON/생성 기록 외 HTML을 만들지 않는지 확인한다. 다음 렌더러 핀 검사는 기존 실행 검증용 review.json에만 적용한다. 버전 없는 입력·미지원 schema_version·다른 renderer_version·누락된 필수 설명·잘못된 타입·알 수 없는 필드·중복 JSON 키·NaN/Infinity를 거부하는지 확인한다. 렌더러 파일을 릴리스 없이 수정하면 생성이 중단되어야 한다. 같은 릴리스 번호를 덮어쓸 수 없어야 하고 새 릴리스도 입력의 버전 핀을 자동으로 바꾸면 안 된다.

이전은 원본/이미 존재하는 출력 파일을 덮어쓰지 않고 업무 내용도 바꾸지 않아야 한다. 호환 입력은 명시적 플래그가 없으면 거부하며 제작 과정과 생성 기록에 호환 모드가 표시되어야 한다. 표준 입력에 호환 플래그만 붙여 필수 설명 검사를 우회하지 못해야 한다.

각 사례를 같은 입력·선택 실행 보고서·릴리스로 두 번 만들어 모델 JSON 바이트와 생성 기록의 입력/출력/실행/릴리스 해시를 대조한다. 사례별 HTML을 생성하지 않고 기존 공통 뷰어에서 열리는지 확인한다. 업무별 생성 도중 렌더러 해시가 바뀌지 않아야 한다. 소스·설치본·배포 ZIP의 고정 파일과 같은 입력의 생성 결과도 일치해야 한다. HTML에는 SQL·원시 실행 결과를 내장하지 않고, 검사 통과를 업무 모델의 정답으로 선언하지 않는다.

## 공유 파일 왕복과 화면 교체

실제 다운로드 파일을 받아 다른 사례의 HTML에서 파일 선택으로 가져오고 모든 공개 데이터·샘플·상태와 네 탭의 동작을 원본에 대조한다. 업무 영역을 좁힌 상태에서도 전체가 내보내지는지, 다시 내보낸 파일의 데이터와 체크섬이 같은지, 동일 파일 반복 가져오기와 새로고침 복귀를 확인한다. 가져오기 후 제목/개요/스펙/ERD/속성/설명/샘플/참조가 이전 사례와 섞이면 실패다. 실패·미실행·보고서 없음·compatibility도 보존해야 한다.

잘못된 JSON·중복 키·NaN·큰 정수·잘못된 타입·버전·참조/열/샘플 PK·표준 설명 누락·체크섬 변경·제작용 입력·크기 초과를 가져와 오류와 현재 화면/SVG/카메라 보존을 확인한다. 긴 문자열/HTML처럼 생긴 샘플은 코드 실행 없이 그대로 표시되어야 한다. 파일 선택 취소·키보드·알림 닫기와 여러 번 교체 후 중복 DOM ID/오래된 비동기 그림/콘솔 오류/외부 통신 없음을 확인한다. 세 해상도에서 버튼·제목·상위 메뉴가 겹치거나 문서 스크롤을 만들지 않아야 한다.

## 재사용하는 빈 공통 뷰어

같은 릴리스에서 두 번 만든 --viewer HTML과 생성 기록의 일치, 내장 데이터 3개 필드가 null이고 사례별 해시/업무 내용이 없는지 확인한다. 입력/실행 보고서를 함께 지정하는 잘못된 CLI는 기존 출력 파일을 유지하며 실패해야 한다. 소스·설치본·배포 뷰어의 바이트도 대조한다.

빈 화면에서 오류 JSON/지원하지 않는 버전/파일 취소를 처리한 뒤에도 내보내기는 비활성이고 가짜 보고서는 없어야 한다. 명시적으로 지원하는 이전 공유 파일과 기본 모델 JSON을 실제 다운로드해 같은 공통 뷰어에서 반복 가져온다. 7개 업무/경계 사례에서 네 탭·전체 ERD·속성·설명·샘플·참조·실패/미실행/호환 표시를 대조하고 재내보낸 데이터가 같아야 한다. 새로고침 후에는 빈 상태로 돌아가고 네트워크/브라우저 저장소에 데이터가 남지 않아야 한다. 세 해상도에서 첫 안내와 가져오기/내보내기 버튼이 잘리지 않아야 한다.

## 직접 작성·JSON 전용 생성 평가

직접 작성한 format/format_version/review만의 standard 문서를 스키마/관계 검사한 뒤 HTML·SQL·체크섬·렌더러 핀 없이 뷰어에서 연다. 제목/샘플을 일반 JSON 편집으로 바꾼 뒤 다시 열리는지, verification이 없으면 미실행인지, 내보내기 왕복 시 선택 필드가 생기거나 확인 상태가 바뀌지 않는지 확인한다.

기존 7개 사례를 build_model.py로 JSON에 직접 투영하고 어떤 사례 HTML도 생성/변경하지 않아야 한다. 실제 결과의 통과/실패/미실행과 SQL/원시 배열 제외, 오래된 실행 보고서 거부, 불량 입력 때 기존 출력 보존을 확인한다. 같은 데이터/배포본은 같은 JSON/생성 기록을 만들고 소스/설치본/ZIP도 일치해야 한다. 모델 형식/스키마가 같으면 선택 생성 메타데이터의 다른 UI 버전 때문에 거부하지 않는다. 미지원 형식/스키마·잘못된 연결은 거부하며 현재 화면을 유지한다.

## HTML 자동 진입 방지와 공통 진입점

직접 작성한 모델 JSON을 build_model.py와 render_review.py의 기본 모드에 각각 전달하고 JSON·생성 기록이 같은지 확인한다. 두 명령 모두 .html 출력만 지정하면 파일을 만들거나 덮어쓰지 않고 거부해야 한다. 명시적인 --format html은 별도의 유지보수 시험에서만 확인한다. 입력/실행 자료가 JSON 출력 또는 생성 기록과 같은 경로일 때 원본을 덮어쓰지 않아야 한다.

## 복잡도와 설계 검토 평가

단순한 새 비품 분류 목록과 기존 회의실 예약 시스템 변경을 비교한다. 전자는 관련 규칙만 짧게 기록하고, 후자는 준비 시간·정원·취소 이력·동시성·탈퇴자 보존의 미결 정책과 영향을 검토한다. 대안 비교는 같은 기준의 비용과 이익을 설명하고 미결/제외를 실제 쟁점에 연결한다. 검토 기록 없는 기존 파일은 계속 읽히되 새 작성에서는 기록한다. 잘못된 규칙-시나리오 연결·미결 정책의 실행검증 위장·미확인 기준의 무영향 단정을 거부하는지 확인한다. 사례 결과는 JSON만 만들고 기존 뷰어의 해시가 그대로인지, 같은 검토 기록이 가져오기·내보내기에서 보존되는지 검사한다.

## 1.1 내용 대응·무결성·범용성 회귀

`audit_integrity.py --output /tmp/integrity.json [--node <node>]`로 오래된 성공 기록, 미참조 행의 중복 PK, 필수 NULL/누락, 명시 유일 조합, 잘못된 FK, 선택지·원자 규칙·변경 after의 참조, 간결한 standard 설명, 1.0 읽기/명시적 이전과 양쪽 진입점의 JSON-only 생성을 검사한다. Node 옵션은 뷰어에 내장된 같은 검사기를 실행해 수락/거부·내용 지문·내보내기가 Python과 같은지 비교한다. 정수/실수·음의 0·유니코드 키도 대조한다. check_integrity_viewer.cjs는 같은 기존 공통 뷰어에서 새/구 사례의 네 탭·드로어·상태·정확한 파일 왕복과 잘못된 가져오기 후 화면 보존을 세 해상도로 확인한다. 테스트용 성공 기록과 실제 사례 결과는 구별한다.
