# 회귀 사례와 확인 범위

실행 명령은 [개발 안내](../README.md)를 따른다. 일반 모델링에서는 개발 도구를 설치하거나 사례 HTML을 만들지 않는다.

## 공개 사례

- 오픈마켓: 통합/마켓 전용/매핑 모델, 금전의 단위와 기간·환불·미귀속 보존, 수집 누락·중복·역순·상충, 귀속 정정, 실제 문서와 내부 제안의 구별.
- 예약 변경: 시간 경계·중복 예약·취소·다대다 집계와 준비 시간/정원/이력의 미결 정책, 운영 기준 미확인과 전환 영향.
- 비품: 짧은 설명으로 식별·분류·삭제를 설명하며 관련 없는 위험·규칙을 강요하지 않는지 확인.
- 추가 호환 입력: 1.0 문서, 논리/순환/자기 참조, 빈 샘플, 긴 문장, 실패·미실행의 혼합. 실제 업무 확인과 테스트용 상태를 구별한다.

## 계약·내용 대응

모든 행의 PK·필수 값·명시 유일 조합·물리 FK, 복합 키와 NULL 의미, 숫자 1/1.0·불리언·유니코드 지문, 잘못된 참조·중복 ID·미결 규칙·선택지·변경 after를 검사한다. 내용 변경 뒤 남은 결과는 거부하고 명시적 제거/이전은 원본과 결과를 보존한다. Python과 뷰어가 같은 문서를 수락/거부하고 그대로 내보내는지 비교한다.

## 독립성과 패키지

뷰어 파일 없이 JSON CLI가 동작해야 한다. CSS/JS/HTML을 수정해도 같은 입력의 JSON과 생성 기록이 같아야 한다. 설치용 ZIP에는 지침·계약·JSON 도구와 빈 완성 뷰어 및 라이선스만 있어야 한다. 별도 경로에 풀어 세 CLI를 사용하고 dev·저장소 루트·Node에 기대지 않는지 확인한다. 빌드 도구도 Python 모델 라이브러리 없이 뷰어를 재생성할 수 있어야 한다. 이전 예제·스키마·역사 릴리스 바이트는 보존한다.

## 본문과 화면

스펙은 요약/설계안/남은 결정의 구획과 규칙/사용 예/근거/관련 모델의 소속을 유지한다. 선택지의 이점·대가와 미결 선택지·현재 제안, 공통·미연결 항목, 범위·가정·변경 이유가 사라지지 않아야 한다. Node 구조 검사는 실제 브라우저의 줄바꿈·간격·오버플로 검사를 대신하지 않는다.

브라우저 확인이 허용된 환경에서는 같은 동봉 뷰어에서 예제 가져오기·네 탭·전체/도메인/확인 사항 ERD·패널 조절·샘플 드로어·미니맵·카메라 보존·정확한 내보내기를 세 해상도로 확인한다. 잘못된 가져오기는 현재 모델/SVG를 교체하면 안 된다. 페이지 스크롤·콘솔 오류·외부 통신·가짜 성공 표시가 없어야 한다. 브라우저 접근 차단을 우회하지 않으며 수행하지 않은 시각 검사를 보고하지 않는다.
